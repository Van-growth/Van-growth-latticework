# /done — 세션 핸드오프 기록

이 커맨드는 Claude Code 세션을 마무리할 때 실행한다. 목적은 세션이 리셋되어도
다음 세션이 이번 세션의 작업 맥락(뭘 했고, 뭐가 남았고, 뭘 발견했는지)을 이어받을
수 있도록 `CLAUDE.md`의 `## Handoff` 섹션에 고정된 포맷으로 기록을 남기는 것이다.

## 수행 순서

1. **오늘 작업 내용 파악** — 이번 대화 세션 전체를 되짚어 실제로 무엇을 했는지
   정리한다 (사용자 요청, 만들거나 수정한 파일, 구현한 기능, 적용한 마이그레이션,
   내린 결정 등). 기억에만 의존하지 말고 아래로 교차 검증할 것:
   - `git status` — 커밋 안 된 변경사항 확인
   - `git diff --stat HEAD` — 변경된 파일 목록 확인
   - `git log --oneline -10` — 이번 세션 중 커밋이 있었다면 해시와 메시지 확인

2. **이전 우선순위 대조** — 현재 `CLAUDE.md`의 `## Handoff` 섹션에 있는 기존
   "다음 세션 우선순위" 항목을 확인한다. 이번 세션에서 그 항목이 실제로 완료됐으면
   아래 "완료"에 포함하고, 완료되지 않았으면 "남음"으로 그대로 이월한다. 이전
   Handoff가 없거나(최초 실행) 우선순위가 비어있으면 이 단계는 생략한다.

3. **완료 vs 남음 정리** — 세션 중 사용자가 요청한 항목들을 기준으로 어디까지
   끝났고 어디부터 안 끝났는지 나눈다. "남음" 각 항목에는 다음 세션에서 바로
   이어갈지, 사용자가 별도 세션으로 지정했는지를 표시한다.

4. **미해결 이슈 정리** — 작업 중 발견했지만 이번 세션에서 처리하지 않은 버그/이슈/
   기술부채를 정리한다. 없으면 "- 없음" 한 줄로 명시한다 (섹션을 비워두지 말 것).

5. **KR/EN 다국어 체크리스트 확인** — 이번 세션에서 새로 추가/수정된 기능마다 아래
   2가지가 확인됐는지 체크한다:
   1. Claude 프롬프트에 언어(KR/EN) 생성 지시문이 포함됐는가 (`analyses.language`
      분기 구조를 타는 콘텐츠인 경우 — `server/src/lib/claude.ts`의 기존 언어 분기
      지점(`SECTION_SYSTEM` 등)에 새 콘텐츠가 실제로 걸리는지 확인)
   2. 새 UI 고정 텍스트(버튼/라벨/탭 이름 등)가 `client/src/lib/i18n/uiStrings.ts`에
      ko/en 양쪽 다 채워졌는가 (컴포넌트에 하드코딩된 한/영 문자열이 남아있지 않은지
      확인)
   둘 다 확인됐으면 다음 단계로 넘어간다. 하나라도 누락됐거나 판단이 어려우면 이
   자리에서 직접 고치려 하지 말고, 8번 "CLAUDE.md 갱신"의 "발견 (미처리)" 섹션에
   반드시 `⚠️ KR/EN 미확인 — <어떤 기능의 어떤 부분인지>` 형식의 항목으로 남긴다. 이번
   세션에 언어 분기/UI 고정 텍스트와 무관한 변경만 있었으면(예: 순수 백엔드 로직,
   문서화만) 이 단계는 "해당 없음"으로 짧게 기록하고 넘어간다.

6. **다음 세션 우선순위 1개 선정** — "남음" 중 가장 먼저 처리해야 할 단 하나만
   고른다. 여러 개를 나열하지 말 것 — 다음 세션이 무엇부터 볼지 헷갈리지 않게
   하는 것이 목적이다.

7. **Render 배포 상태 확인 시도** — 이번 세션에 push한 커밋이 있으면 Render
   배포가 트리거됐는지 확인을 시도한다 (Render API 토큰·CLI·MCP 등 그 시점에
   가용한 수단이 있으면 사용). 확인할 수단이 없으면 "미확인"으로 표기하고 이유를
   한 줄로 남긴다 — push한 커밋이 없으면 "미확인 — 이번 세션 push 없음"처럼
   상황 그대로 적는다. 확인 시도 자체를 생략하지 말 것.

8. **CLAUDE.md 갱신** — `CLAUDE.md` 최상단의 `## Handoff` 섹션에서 "세션 시작 규칙"
   안내문(blockquote)은 그대로 유지하고, 그 아래 내용만 아래 **고정 포맷**으로
   전체 덮어쓴다 — 이전 Handoff 내용에 이어붙이지 말고 항상 최신 상태 하나만
   남긴다. `## Handoff` 섹션 밖 CLAUDE.md의 나머지 내용(Vision, SSOT, 보안 원칙
   등)은 절대 건드리지 않는다.

   ```
   **날짜**: <YYYY-MM-DD, 오늘 날짜>
   **커밋**: <hash1>, <hash2>, ... (이번 세션에 만든 커밋 짧은 해시, 없으면 "없음")
   **Render 배포**: <확인함/미확인> — <한 줄>

   ### 완료
   - <항목>: <한 줄 설명>

   ### 남음
   - <항목>: <한 줄 설명> — <다음 세션 / 별도 세션(사유)>

   ### 발견 (미처리)
   - <증상>: <원인 규명 상태> — <영향 범위>

   ### 다음 세션 우선순위
   1. <단일 항목, 한 줄>
   ```

   **포맷 규칙**:
   - 마크다운 헤더 + 짧은 불릿만 사용한다. 서술형 문장 금지 — 항목화해서 쓸 것.
   - 각 불릿은 줄바꿈 없이 1줄로 쓴다. 길어지면 축약하고, 세부 내용은 커밋
     메시지나 `git log`를 참고하도록 유도한다 (풀어 쓰지 않는다).
   - "발견 (미처리)"가 없으면 "- 없음" 한 줄로 남긴다.

9. **CLAUDE.md 커밋** — Handoff 섹션 갱신 후 `CLAUDE.md` 파일 하나만 자동으로 커밋한다.
   - `git add CLAUDE.md` — 다른 파일은 절대 add하지 않는다.
   - add 직후 `git diff --cached --name-only`로 스테이징된 파일이 `CLAUDE.md` 하나뿐인지
     확인한다. 하나가 아니면(이미 사용자가 다른 파일을 add해둔 경우 등) **커밋을
     중단**하고 어떤 파일이 함께 스테이징되어 있었는지 사용자에게 보고한다 — 절대
     `CLAUDE.md` 외의 파일을 포함해 커밋하지 않는다.
   - 확인되면 `git commit -m "docs: session handoff YYYY-MM-DD"` 실행 (YYYY-MM-DD는
     실제 커밋을 실행하는 날짜).
   - **push는 하지 않는다** — 사용자가 이 커밋을 다른 커밋과 묶어서 나중에 직접
     push할 수 있으므로, `/done`은 로컬 커밋까지만 하고 멈춘다.
   - `CLAUDE.md` 외의 파일에 unstaged/uncommitted 변경이 있어도 그 파일들은 이
     커밋과 무관하게 그대로 둔다(add하지 않는다) — `/done`은 세션 코드 작업의
     커밋을 대신하지 않는다. 그런 변경의 커밋 여부는 항상 사용자가 명시적으로
     지시할 때만 별도로 처리한다.

10. **확인용 출력** — 갱신을 마치면 새로 반영된 `## Handoff` 섹션 전체와, 방금
    생성한 커밋의 해시·메시지를 출력해 사용자가 바로 검토할 수 있게 한다. (9번에서
    커밋을 중단한 경우에는 커밋 결과 대신 중단 사유를 출력한다.)
